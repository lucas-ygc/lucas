## 四类验证各自证明什么

| 验证 | 能证明 | 不能证明 |
| --- | --- | --- |
| 合成规则回归 | 某组输入指标走对分支、重置逻辑正确 | 神经网络会对真实图像输出正确指标 |
| PC/板端同输入对齐 | 转换、预处理、解码在样本上接近 | 接近的两个结果都符合真实标注 |
| 设备联调 | 连接、推理、参数、保存与恢复路径可运行 | 大规模场景误报漏报达标 |
| 独立标注集评估 | 在规定数据分布上的任务效果 | 所有新场景或不同镜头都同样有效 |

将三张成功图片叫做“准确率验证通过”，或把 OM/ONNX mask IoU 当作真实分割准确率，会把证据范围放大。文章与报告都应写清样本量、输入、参考目标和运行方式。

## 先确定标注规范

建议每个头部分别标注鼻和嘴：可见、外部遮挡、自遮挡/极端姿态、无法标注，并记录头框、人脸可见性和可能遮挡物。边界模糊的样本不要强行塞进二分类，应保留不可判定原因，并进行独立复核。

口罩仅遮嘴、手靠近但未遮住、张嘴、脸离开画面，必须按业务定义区分。事件级标注还要记录开始与结束时间；不能从单张截图补造持续时长。

划分数据时按人员、场景或连续视频段分组，避免相邻帧同时进入调参和测试集。量化校准集、规则调参集、最终独立评估集用途不同，重用时需明确说明。

## 场景矩阵

| 维度 | 至少覆盖 |
| --- | --- |
| 可见性 | 无遮挡、单独遮鼻、单独遮嘴、同时遮挡、部分遮挡 |
| 物体 | 手、手臂、纸巾、口罩、衣物、未在词表中的物体 |
| 姿态 | 正脸、左右转头、歪头、低头、后脑、贴边 |
| 非遮挡干扰 | 张嘴、胡须、浓阴影、强逆光、眼镜、肤色差异 |
| 图像质量 | 小脸、运动模糊、低照、压缩、曝光变化、镜像 |
| 人数与运动 | 单人、多人交叉、进入离开、头框重叠 |
| 系统事件 | 断流、断连、模型缺失、热调参、配置冲突、重启 |

当前可见优先规则应额外收集“鼻嘴点漂到其他皮肤”的样本，观察错误放行；World 则需要收集“物体框覆盖 ROI 但实际不在脸前”的样本，观察错误支持。

## 指标怎样计算

鼻和嘴分别统计 TP、FP、FN，并报告 Precision=`TP/(TP+FP)`、Recall=`TP/(TP+FN)`。分母为零时报告 N/A，不伪造满分。

不确定样本不能悄悄删除。至少同时报告明确判定覆盖率、`UNCERTAIN` 比例、无脸比例、输入有效率，以及在明确判定样本上的精确率和召回率。若只报告已成功检测到脸的子集，必须说明入口漏检未被计入。

持续事件还需统计每小时误报次数、事件漏检率、首次确认延迟、异常解除延迟和重复确认情况。单帧指标好不代表时序体验好；较长 hold 时间可能减少误报，也可能延迟或漏掉短事件。

## 阈值调参需要控制变量

先固定模型、预处理与数据，再按顺序检查头脸检测、局部 ROI、分割阈值、响应阈值、姿态、时序和物体证据。每轮保存完整参数，不只记“把嘴阈值调高了”。

在调参集上扫阈值并观察误报漏报曲线，选定规则后锁住配置，在独立测试集上一次性评估。若根据测试结果继续改参数，该数据已经参与开发，应重新准备独立验证集。

消融可分别关闭 World、比较旧新融合规则、比较不同头模型、观察是否加入响应证据。比较必须使用同样输入和统计口径；World 当前不反写主状态，因此打开它不会改善主状态分类指标，应单独评估物体证据质量。

## 可运行的规则回归入口

在具备 NumPy/OpenCV 的现有 Python 环境，从工程根目录执行：

```bash
mkdir -p application/.temp/occlusion-check
python3 -m unittest discover \
  -s application/Dependent/shared/head_pipnet_unet -p 'test_*.py' \
  > application/.temp/occlusion-check/policy.log 2>&1
python3 application/Dependent/shared/yoloworld_occluder/test_review.py \
  > application/.temp/occlusion-check/review.log 2>&1
```

这些测试包含几何、规则及模拟物体结果，不下载权重，也不代表实板模型效果。ARM 回放另见 `head_pipnet_unet/hi3516/build_checks.sh`、`check_policy.py`；完整张量对齐见 `check_cascade.py`，依赖相应输入与导出产物。

## 性能测量需要标明边界

分别记录冷加载、热加载、纯模型运行、预后处理、整轮分析和采集到显示延迟。固定图片、实时流、单人与多人必须分组。使用 P50/P95 与最大观察值，而非仅展示最好一次。

MMZ 记录业务基线、阶段峰值、卸载后基线；RSS/HWM 记录进程内存；CPU 百分比说明是相对单核还是整机。采样间隔可能漏过短时峰值，不能称为严格内存上界。反复运行后回不到基线时，先检查帧释放、模型缓冲和输出持有关系。

## 当前未闭合的问题

尚缺代表性独立标注集与生产误报漏报报告；可见优先存在定位漂移误放行风险；FaceOcc 对侧脸、口腔与阴影的语义需要继续验证；World 的分类分数有转换漂移，手与手臂可能混淆；IoU 关联不提供长期身份；产品报警与恢复流程尚不能从预览标记推定。

后续每次改动保留失败样本、原参数、新参数、模型指纹、状态差异和验证范围。这样一次修复才能进入可回归的工程记录，而不是只剩“现场看起来好了”。
