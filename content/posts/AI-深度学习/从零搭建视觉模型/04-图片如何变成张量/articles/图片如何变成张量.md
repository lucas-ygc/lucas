## 从 HWC 到 NCHW

下面是完整脚本中最需要理解的几行。`image` 是已经由 Pillow 读取并转换成 RGB 的图片。

```python
pixels = np.array(image, dtype=np.uint8, copy=True)
hwc = torch.from_numpy(pixels)
chw = hwc.permute(2, 0, 1).contiguous()
scaled = chw.to(dtype=torch.float32) / 255.0
batch = scaled.unsqueeze(0)
```

### 第一步：像素数组 HWC

NumPy 数组的形状是 `(2, 3, 3)`，三个维度分别是：

| 符号 | 含义 | 本例数值 |
| --- | --- | --- |
| H | Height，高，对应行数 | 2 |
| W | Width，宽，对应列数 | 3 |
| C | Channel，通道数 | 3 |

`pixels[0, 0]` 取的是第 0 行、第 0 列的全部通道，结果为 `[255, 0, 0]`。

注意：Pillow 的 `image.size` 使用 `(W, H)`，这个 NumPy 数组使用 `(H, W, C)`。图片没有旋转，只是两个接口描述尺寸的顺序不同。

`torch.from_numpy` 把数组接入 PyTorch 中，保留形状和数据类型，并共享底层内存；这一步本身没有缩放像素。[接口说明](https://docs.pytorch.org/docs/stable/generated/torch.from_numpy.html)

### 第二步：调整为 CHW

原来维度的编号是 `0=H、1=W、2=C`。

```python
chw = hwc.permute(2, 0, 1).contiguous()
```

`permute(2, 0, 1)` 把通道维放到前面，因此得到 `(3, 2, 3)`。此时取左上角三个颜色值需要写成 `chw[:, 0, 0]`，结果仍是 `[255, 0, 0]`。

这是维度顺序的调整，RGB 的颜色含义保持不变。`contiguous()` 在需要时整理内存布局，便于后续操作；`permute` 的维度置换语义见[官方文档](https://docs.pytorch.org/docs/stable/generated/torch.permute.html)。

不要用 `reshape(3, H, W)` 代替这一步：改形状不能代替按轴重排，得到相同的形状也不代表像素对应正确。

### 第三步：转换类型并缩放数值

```python
scaled = chw.to(dtype=torch.float32) / 255.0
```

红色像素从 `[255, 0, 0]` 变为 `[1.0, 0.0, 0.0]`。形状仍是 CHW，变化的是类型和数值尺度。

这里做的是把 8 位像素缩放到 `[0, 1]`，尚未做减均值、除标准差等处理。图片不一定包含纯黑或纯白，所以换一张图片后，实际最小值和最大值不一定恰好是 0 和 1。

### 第四步：增加批次维度 N

```python
batch = scaled.unsqueeze(0)
```

`unsqueeze(0)` 在开头插入一个长度为 1 的维度，得到 `(1, 3, 2, 3)`；本例的 `N=1` 表示这一批只有一张图片。[接口说明](https://docs.pytorch.org/docs/stable/generated/torch.unsqueeze.html)

对于接下来准备搭建的 PyTorch CNN，采用如下输入约定：

```text
NCHW = 批次中的图片数 × 通道数 × 图片高度 × 图片宽度
```

具体模型的输入类型、布局、颜色顺序和预处理要求需要单独确认。此前项目笔记中的部署模型示例，以及本课的 `float32 RGB NCHW`，不能直接当作所有模型通用的输入规范。

### 练习 2：缩放改变了什么

编写 `scale_channels(chw)`，接收 `uint8` CHW 张量，返回 `float32` 张量，将通道值从 0～255 缩放到 0～1。

要求不修改传入张量。用第一题的 CHW 张量检查：

- 返回形状仍为 `(3, 2, 3)`，类型为 `torch.float32`。
- 红色像素变为 `[1.0, 0.0, 0.0]`。
- 橙色像素约为 `[1.0, 0.501961, 0.0]`。
- 原张量仍为 `torch.uint8`，橙色像素仍为 `[255, 128, 0]`。

再用通道值全为 128、形状为 `(3, 2, 3)` 的 `uint8` 张量调用函数：结果的最小值和最大值都应约为 `0.501961`，不应强行变成 0 和 1。可以用 `torch.full` 创建这份输入。

<details class="exercise-answer">
<summary>点击查看第二题参考答案与本次练习总结</summary>

**参考答案**

本次的缩放函数实现正确。下面省去不必要的复制，补齐原张量未改变和全 128 输入的检查。脚本与 `sample.ppm` 放在同一目录，可保存为本篇 `code/practice_02.py`。

```python
from pathlib import Path

import numpy as np
import torch
from PIL import Image


def scale_channels(chw_uint8):
    chw_float = chw_uint8.to(dtype=torch.float32)
    return chw_float / 255.0


def main():
    image_path = Path(__file__).resolve().parent / "sample.ppm"
    with Image.open(image_path) as source:
        image = source.convert("RGB")

    pixels = np.array(image, dtype=np.uint8, copy=True)
    hwc_uint8 = torch.from_numpy(pixels)
    chw_uint8 = hwc_uint8.permute(2, 0, 1).contiguous()
    original_chw = chw_uint8.clone()
    scaled_chw = scale_channels(chw_uint8)

    print(f"缩放后形状: {tuple(scaled_chw.shape)}")
    print(f"缩放后类型: {scaled_chw.dtype}")
    print(f"红色像素: {scaled_chw[:, 0, 0].tolist()}")
    print(f"橙色像素: {scaled_chw[:, 1, 2].tolist()}")
    print(f"原张量类型: {chw_uint8.dtype}")
    print(f"原橙色像素: {chw_uint8[:, 1, 2].tolist()}")
    print(f"原张量数值未变: {torch.equal(chw_uint8, original_chw)}")

    uniform_chw = torch.full((3, 2, 3), 128, dtype=torch.uint8)
    scaled_uniform_chw = scale_channels(uniform_chw)
    print(f"全 128 缩放后最小值: {scaled_uniform_chw.min().item():.6f}")
    print(f"全 128 缩放后最大值: {scaled_uniform_chw.max().item():.6f}")


if __name__ == "__main__":
    main()
```

预期输出：

```text
缩放后形状: (3, 2, 3)
缩放后类型: torch.float32
红色像素: [1.0, 0.0, 0.0]
橙色像素: [1.0, 0.501960813999176, 0.0]
原张量类型: torch.uint8
原橙色像素: [255, 128, 0]
原张量数值未变: True
全 128 缩放后最小值: 0.501961
全 128 缩放后最大值: 0.501961
```

变量名用来说明数据当前的含义：`chw_uint8` 是尚未缩放的整数张量，`chw_float` 是只转换了类型的浮点张量，`scaled_chw` 是完成缩放的结果。`original_chw` 保存调用前的数据，供后续比较；`uniform_chw` 表示所有通道值相同的输入，比 `test` 或 `new_scale` 更容易理解。

**本次练习总结（2026-10-06）**

- **原实现正确，没有修改输入。** 先 `clone()`，再转为 `float32` 并除以 255，能得到题目要求的结果。本次提交只打印了缩放结果，尚未写出全部验证，尤其缺少全 128 输入的检查；上面的答案已补齐。
- **函数中的 `clone()` 可以省略。** 本题输入为 `uint8`，转成 `float32` 时会产生新的张量，普通 `/` 运算也不会原地修改输入。这里不能推广成“所有 `.to()` 都会复制”：输入已经符合目标类型和设备时，`.to()` 可能直接返回原张量。
- **验证用的副本仍有用途。** `original_chw = chw_uint8.clone()` 保存调用前的数值，之后用 `torch.equal()` 比较；如果只写 `original_chw = chw_uint8`，两个变量指向同一个张量，就无法靠它发现原地修改。
- **转换类型和缩放是两步。** `.to(dtype=torch.float32)` 将整数 255 变为浮点数 255.0，随后 `/ 255.0` 才将它变为 1.0；两步都不改变形状。
- **缩放后不一定出现 0 和 1。** 每个值固定除以 255，因此全 128 输入的最小值和最大值都约为 `0.501961`。`[0, 1]` 描述允许的数值范围，不要求每张图片都包含两个端点。
- **`.item()` 和显示精度。** `.min()`、`.max()` 返回只有一个值的张量，`.item()` 将其取为 Python 数值；`:.6f` 仅让输出保留六位小数，不会改变张量中的数据。

</details>

### 练习 3：封装一张图片的模型输入

编写 `image_to_batch(path, size=None)`，返回一张图片对应的 `float32 RGB NCHW` 张量，数值范围为 `[0, 1]`。

要求依次完成读取、转换 RGB、可选尺寸调整、转张量、调整维度、缩放和增加批次维度。`size` 为 `None` 时保留原尺寸；否则是 `(宽, 高)` 元组。

用示例图片验证：

| 调用条件 | 返回形状 |
| --- | --- |
| 不传 `size` | `(1, 3, 2, 3)` |
| `size=(5, 4)` | `(1, 3, 4, 5)` |
| `size=(320, 224)` | `(1, 3, 224, 320)` |

检查不调整尺寸时的橙色像素，结果应约为 `[1.0, 0.501961, 0.0]`。调整尺寸可能改变像素值，本题对调整后的图片只检查形状、类型和数值范围。

<details class="exercise-answer">

**参考答案**

以下代码可独立运行，保存时与 `sample.ppm` 放在同一目录。

```python
from pathlib import Path

import numpy as np
import torch
from PIL import Image, ImageOps


def image_to_batch(path, size=None):
    with Image.open(path) as source:
        image = ImageOps.exif_transpose(source).convert("RGB")
    if size is not None:
        image = image.resize(size, Image.Resampling.BILINEAR)
    pixels = np.array(image, dtype=np.uint8, copy=True)
    hwc_uint8 = torch.from_numpy(pixels)
    chw_uint8 = hwc_uint8.permute(2, 0, 1).contiguous()
    scaled_chw = chw_uint8.to(dtype=torch.float32) / 255.0
    return scaled_chw.unsqueeze(0)


image_path = Path(__file__).resolve().parent / "sample.ppm"
for size in (None, (5, 4), (320, 224)):
    batch = image_to_batch(image_path, size)
    expected_shape = (1, 3, 2, 3) if size is None else (1, 3, size[1], size[0])
    assert tuple(batch.shape) == expected_shape
    assert batch.dtype == torch.float32 and batch.device.type == "cpu"
    assert 0.0 <= batch.min().item() <= batch.max().item() <= 1.0
    print(f"size={size}: shape={tuple(batch.shape)}, dtype={batch.dtype}")
    if size is None:
        orange = batch[0, :, 1, 2]
        assert torch.allclose(orange, torch.tensor([1.0, 128 / 255, 0.0]))
        print(f"橙色像素: {orange.tolist()}")
```

**要点说明**

### 练习 6：把两张图片组成一批

取得第二题缩放后的 CHW 张量，记为 `first`。复制得到 `second`，把 `second` 的全部 B 通道设为 0，再将两份 CHW 张量组成一批。

本题可以使用新接口 `torch.stack([first, second], dim=0)`，它在指定位置增加一个维度并堆叠数据，要求输入张量形状相同。

要求：

- 批次形状为 `(2, 3, 2, 3)`，类型为 `torch.float32`。
- 批次中第一张图片的第一行、第三列像素为 `[0.0, 0.0, 1.0]`。
- 批次中第二张图片的同一像素为 `[0.0, 0.0, 0.0]`。
- `first` 原来的蓝色像素仍为 `[0.0, 0.0, 1.0]`。

这里从 CHW 开始堆叠，不要先分别增加批次维度，否则会多出一层维度。完成这题后，你就实际构造了一份含两张图片的 NCHW 模型输入。

<details class="exercise-answer">
<summary>点击查看第六题参考答案与要点</summary>

**参考答案**

以下代码可独立运行，保存时与 `sample.ppm` 放在同一目录。

```python
from pathlib import Path

import numpy as np
import torch
from PIL import Image

image_path = Path(__file__).resolve().parent / "sample.ppm"
with Image.open(image_path) as source:
    pixels = np.array(source.convert("RGB"), dtype=np.uint8, copy=True)
hwc = torch.from_numpy(pixels)

chw_uint8 = hwc.permute(2, 0, 1).contiguous()
first = chw_uint8.to(dtype=torch.float32) / 255.0
second = first.clone()
second[2, :, :] = 0
batch = torch.stack([first, second], dim=0)

print(f"批次形状: {tuple(batch.shape)}")
print(f"批次类型: {batch.dtype}")
print(f"第一张图片原蓝色位置: {batch[0, :, 0, 2].tolist()}")
print(f"第二张图片原蓝色位置: {batch[1, :, 0, 2].tolist()}")
print(f"first 原蓝色位置: {first[:, 0, 2].tolist()}")
assert tuple(batch.shape) == (2, 3, 2, 3)
assert batch.dtype == torch.float32
assert batch[0, :, 0, 2].tolist() == [0.0, 0.0, 1.0]
assert batch[1, :, 0, 2].tolist() == [0.0, 0.0, 0.0]
assert first[:, 0, 2].tolist() == [0.0, 0.0, 1.0]
```

预期输出：

```text
批次形状: (2, 3, 2, 3)
批次类型: torch.float32
第一张图片原蓝色位置: [0.0, 0.0, 1.0]
第二张图片原蓝色位置: [0.0, 0.0, 0.0]
first 原蓝色位置: [0.0, 0.0, 1.0]
```

**要点说明**

`clone()` 让第二张图片可以单独修改；B 通道的下标是 2，`second[2] = 0` 也是同样的写法。`stack` 在 CHW 外增加 N 轴，得到 NCHW；如果先把每张图片变成 `(1, 3, 2, 3)` 再 `stack`，会得到多一层的 `(2, 1, 3, 2, 3)`。
