## 为什么把浮点数换成较少位数

权重和激活如果用更低位数表示，可能减少存储与内存流量，并利用硬件整数运算。但更少的可表示值意味着近似误差，实际速度也依赖执行后端是否提供高效内核。

量化不能自动补齐不支持的算子，也不是把文件压缩成 zip。推理时采用的数值表示和运算路径必须与模型格式、量化参数及硬件实现一起匹配。

## 用一个数看懂量化与反量化

一种常见仿射表示为 `q=clip(round(x/s)+z)`，反量化为 `x_hat=(q-z)×s`。s 是正的缩放因子，z 是零点，clip 限制整数范围。实际实现的舍入规则与量化范围需要核对。

取 s=0.1、z=0，x=0.26，得到 q=3，恢复为 0.3，误差 0.04。这说明量化后数值通常不能完全恢复。若输入范围超出整数能表示的区间，还会发生截断，而不只是舍入。

```python
values = [-0.26, 0.0, 0.26, 20.0]
scale, zero = 0.1, 0
qmin, qmax = -128, 127
quantized = [max(qmin, min(qmax, round(x/scale) + zero)) for x in values]
restored = [(q-zero)*scale for q in quantized]
print(quantized)
print(restored)
assert quantized == [-3, 0, 3, 127]
```

20.0 超过此设置的上界 12.7，误差远大于一个量化步长。真实模型需要根据张量分布与硬件支持选择范围，不能对所有层固定同一个随意的 scale。

## 对称、非对称与逐通道

对称量化通常围绕零安排范围，非对称量化可用零点表达偏移。逐张量使用一组量化参数，逐通道则为不同通道设置参数，可能更适合幅度差异明显的权重。是否支持、沿哪个轴量化，都由具体工具和算子决定。

权重量化与激活量化是不同维度。某种低比特权重格式可能仍用浮点激活；另一种实现则把两者都量化。只写“INT8 模型”不足以说明图中每一处精度。

## 校准数据决定观察到的范围

训练后静态量化常用代表性数据估计激活分布；动态量化会在运行时计算部分量化参数；量化感知训练则在训练中模拟相关误差。它们适用的算子、成本和工具链不同。[ONNX Runtime 量化文档](https://onnxruntime.ai/docs/performance/model-optimizations/quantization.html)

校准集通常不需要任务标签，但需要与实际输入一致的预处理和分布。只用全黑图或少量相似图片，可能无法覆盖现场激活范围。校准不是独立测试，不能用最终测试集反复调整量化策略并继续声称测试独立。

对飞机汽车分类，应覆盖两类、不同亮度与背景。若将来上摄像头，公开小图片的校准并不保证现场可靠。数据来源、数量、预处理和校准方法应随模型一起记录。

## 分三层比较精度

先比较单个张量的浮点与反量化误差，定位是否存在明显截断；再比较网络 logits 或其他输出；最后在同一份验证数据上计算任务指标。一个整体平均误差很小的模型，也可能在少数关键样本上翻转类别。

应保存浮点正确、量化错误的样本列表，并按类别和条件分析。误差集中在某一层时，可以检查其范围、量化轴和算子实现；是否保留部分层高精度，需要工具链支持并重新测性能。

静态量化后图里可能出现量化与反量化节点。这些节点本身不证明硬件已经使用整数加速，应查看实际后端执行与 profiling。频繁跨精度转换可能抵消收益。
