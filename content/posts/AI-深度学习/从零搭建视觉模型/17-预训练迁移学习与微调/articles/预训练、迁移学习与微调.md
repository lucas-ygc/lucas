## 为什么不每次都从随机参数开始

从零训练需要自己的数据来逐步塑造特征。预训练网络已经在其他任务或数据上学到表示，可以作为新任务起点。迁移学习讨论怎样利用这些已有知识，微调则是继续更新部分或全部参数的一种方式。

目标仍是飞机汽车分类。预训练模型原来的类别头通常不符合我们的两类编号，必须更换并训练；直接把原来的某两个输出取出来，不等同于完成同样定义的新任务。

## 三种方案应该分别比较

| 方案 | 哪些参数更新 | 主要问题 |
| --- | --- | --- |
| 从零训练 | 全部 | 数据是否足够，优化是否稳定 |
| 冻结主干 | 新分类头 | 原有表示是否适合当前任务 |
| 部分或全部微调 | 头及选定主干层 | 如何避免过度破坏已有表示 |

先冻结主干可以降低训练成本，帮助检查类别头和输入流程；若性能受限，再逐步解冻。不是所有领域都与预训练数据接近，医学、工业纹理或特殊传感器图像可能需要不同策略。

## 权重与预处理是一套约定

以 Torchvision 的预训练 ResNet-18 为例，权重枚举提供相应变换入口。使用显式权重版本比只记“默认权重”更便于复现。调用权重加载可能下载文件，需要提前准备网络或本地缓存。

下面展示配置与一次训练步，依赖 PyTorch、Torchvision 和已缓存的权重。随机输入仅用于说明计算，不是迁移训练数据，也不能用损失作为真实成绩：

```python
import torch
from torch import nn
from torchvision.models import resnet18, ResNet18_Weights

weights = ResNet18_Weights.IMAGENET1K_V1
model = resnet18(weights=weights)
preprocess = weights.transforms()
for parameter in model.parameters():
    parameter.requires_grad = False
model.fc = nn.Linear(model.fc.in_features, 2)
model.eval()
model.fc.train()
optimizer = torch.optim.AdamW(model.fc.parameters(), lr=1e-3)
images = torch.zeros(2, 3, 224, 224)
labels = torch.tensor([0, 1])
optimizer.zero_grad()
loss = nn.functional.cross_entropy(model(images), labels)
loss.backward()
optimizer.step()
print(model.fc.weight.grad is not None)
```

实际图片应经过 `preprocess`，并核对其裁剪是否仍包含目标。此处创建的零张量只用于结构演示，没有冒充经过真实预处理的样本。相关训练与冻结模式见 [官方迁移学习教程](https://docs.pytorch.org/tutorials/beginner/transfer_learning_tutorial.html)。

## 冻结梯度不等于固定整个主干行为

如果后面直接调用 `model.train()`，BatchNorm 等层可能恢复训练行为，即使权重被冻结，其运行统计仍可能变化。完全冻结特征提取器时，可保持主干为评估模式，只训练新头；实际工程应把这个策略写入训练入口，而不是只在初始化时调用一次。

解冻部分层后，需要让优化器包含新解冻参数。可以重新构建优化器或正确添加参数组，并给主干较小学习率、给新头较大学习率。不要把这些数值当通用常数，应观察验证曲线与梯度行为。

## 公平比较迁移是否有用

保持数据划分、类别定义与指标一致，同时报告输入分辨率、训练时间和参数更新量。如果迁移模型使用更高分辨率和更大计算量，其改善不能全部归因于预训练。

小数据下可以先比较冻结与微调，观察哪类错误被修复。验证集太小时，单次微小提升可能来自随机波动；适当重复，并保留错误清单。如果迁移反而更差，要检查输入约定、类别映射、裁剪和学习率，而不是立即断言预训练无用。

## 练习

1. 修改 `requires_grad` 后，为什么还要检查优化器参数组？
2. 预训练图片常用 224 尺寸，将 32×32 放大是否新增了细节？
3. 什么情况下先冻结主干比较合适？

<details class="exercise-answer">
<summary>参考答案</summary>

优化器可能没有包含后来解冻的参数，参数有梯度也不会被它更新。插值只改变采样网格，不产生真实细节。数据少、想先验证接口或控制训练成本时，可先冻结主干训练新头，再根据验证结果决定是否微调。

</details>
