# 建立开发板信息与版本基线

## 范围与环境

只读采集本机固定 /proc 项，输出行数有界；不连接板子，不采集完整命令行或环境变量。

C 示例需要 Linux、C11 编译器和 libc/pthread 开发文件；Shell 使用 POSIX sh、mktemp 及基础工具；Python 示例仅用 Python 3.10+ 标准库。具体以本包文件类型为准。

## 运行

解压后进入本目录：

```sh
sh collect.sh
```

C 的 run.sh 在新建临时目录编译和运行并清理自己的临时产物；默认使用 cc，可用 CC 指定兼容编译器的可执行文件路径。交叉编译出的程序必须在匹配目标运行，不能直接由主机 run.sh 执行。所有结果以 verification.md 为准，本文的板端工具命令不由实验脚本自动执行。

## 练习

运行本课采集脚本并与另一版本比较。参考结论：先区分环境变化和业务变化，再讨论性能回归。真实 SDK 和硬件编号仍需人工补充。

## 参考分析

两次测试都显示相同 uname，但模型和根文件系统不同。不能据此说“环境完全一致”。基线应额外记录模型校验、SDK 版本、配置和板卡修订，运行快照只覆盖其中一部分。

/proc/self 是实际读取命令自身，不是业务 PID。采集业务需另外指定并记录 PID；可用 `sh collect.sh > snapshot.txt` 保存快照。
